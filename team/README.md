# الجسر — للرئيس

ثلاثة يعملون هنا: **أنت** و**claude** و**codex**. هذا الملف لك أنت.
التفاصيل الكاملة في `PROTOCOL.md`، ولا تحتاجها لتبدأ.

---

## ما يحلّه

كنتَ تنقل الرسائل بينهما بيدك: تنسخ من صندوق codex وتلصق عند claude.
الآن يقرأ كلٌّ منهما رسائل الآخر بنفسه.

---

## أوامرك الأربعة

```bash
team/bin/bridge read raees          # ما ينتظر قرارك
team/bin/bridge log                 # آخر ما جرى بينهما
team/bin/bridge board               # من يعمل على ماذا
team/bin/bridge send raees claude "عنوان" <<'EOF'
طلبك هنا
EOF
```

**والإيقاظ:**

```bash
team/bin/bridge wake claude         # يشغّل claude على الرسائل المفتوحة
```

---

## كيف يعمل الإيقاظ فعلاً

| | |
|---|---|
| **claude — جلسة مفتوحة** | يقرأ الجسر تلقائياً عند بدء الجلسة (خطّاف `SessionStart`) |
| **claude — جلسة مغلقة** | `bridge wake claude` يشغّله بلا واجهة، يقرأ ويردّ ويغلق |
| **codex** | يقرأ `AGENTS.md` فيفتح الجسر عند بدء جلسته — **لكنه لا يُوقَظ آلياً** |

**لماذا لا يُوقَظ codex:** لا يوجد له CLI على هذا الجهاز، فلا شيء يستدعيه من الخارج.
حين يكون له واحد، يصير `bridge wake codex` سطراً واحداً.

⚠️ **ولا جلسةَ توقظ نفسها.** الاستدعاء القصير منك — «اقرأ الجسر وردّ» — يبقى لازماً
لجلسة codex المغلقة. من قال لك إن جسراً يوقظ كل شيء تلقائياً وصف ما يتمنّاه.

---

## متى يتوقّفان وينادونك

يكتبان `bridge ask` فتظهر الرسالة في صندوقك، ويتوقّفان:

- قرار يغيّر المنتج أو السعر أو النطاق
- push أو merge أو deploy
- تعارض بينهما لم يُحسم برسالتين
- شكّ في مفتاح أو بيانات عميل

**وما دون ذلك يقرّرانه بينهما ولا يوقفان العمل.** هذا هو الغرض.

---

## القاعدة التي تمنع الفوضى

```
🔴 اقرأ الكل · واكتب في صندوقك وحدك
```

كاتب واحد لكل ملف = صفر تصادم. أنت في `outbox/raees.md`،
وclaude في صندوقه، وcodex في صندوقه.

**ولا مفاتيح ولا بيانات عملاء في أي رسالة** — القاعدة 01، وتنطبق هنا كما في الكود.
