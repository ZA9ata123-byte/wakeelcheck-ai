# السكربتات

| الأمر | ما يفعله |
|---|---|
| `pnpm run specimen` | يولّد نموذج التقرير من خطّ الأنابيب على مدخل ثابت |
| `pnpm run review <ملف>` | يفحص دفعة متاجر حقيقية ويُبرز ما يستحق النظر |
| `pnpm run build:docs` | يبني ملفات PDF من `docs/html` |

---

## `review` — البوّابة قبل أوّل تاجر

```bash
pnpm run review stores.txt --max-usd 2
```

نطاق في كل سطر، و`#` للتعليق.

### لماذا

الشرط قبل أوّل محادثة تاجر هو «افحص عشرين متجراً واقرأ كل تقرير». بلا
أداة يعني ذلك أربعمئة صفّ بالعين، وأكثرها لا يحتاج نظراً.

ما يحتاجه النظر شيءٌ واحد: **القاعدة التي نجحت على العشرين كلّها، أو
أخفقت عليها كلّها.**

- نجحت على الكلّ ⇒ لم تفرّق بين متجرين، فهي تُضخّم النتيجة بلا أن تقيس.
- أخفقت على الكلّ ⇒ إمّا مكسورة وإمّا مقيَّمة في الموضع الخطأ.

الثانية ليست فرضاً نظرياً: حدثت فعلاً حين كانت قواعد المنتج تُقيَّم على
الصفحة الرئيسية، فكانت تُرسب كلّ متجر.

الحكم نفسه في `packages/readiness/src/audit.ts` ومعه ثمانية اختبارات —
منطقٌ يقرّر ما نصدّقه لا يعيش في سكربت.

### بلا مفاتيح

الجاهزية والأمن والتوصيف كلّها من `safeFetch` وRDAP وTLS وDNS. المحجوب
هو نداء المحرّك وحده، فيبقى فارغاً ويُعلَّم كذلك — لا يُعرض غياباً.

فحصُ العشرين يبدأ اليوم إذن، ولا ينتظر شحن مفتاح.

### السقف

`--max-usd` يوقف الدفعة عند حدّها (الافتراضي 5). خطأٌ في ملف النطاقات
لا ينبغي أن يكلّف أكثر ممّا تحتمل.

### المخرَج

`docs/review/<التاريخ>.json` — وهو أثر تشغيل لا مصدر، فهو خارج git.
